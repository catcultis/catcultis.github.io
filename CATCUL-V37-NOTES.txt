CATCUL V37 — TEMPORARY GUEST ROOMS

This builds on v36 and adds a separate temporary guest chat. The frontend has not been deployed.

HOW IT WORKS
• A signed-in host opens More → Guest rooms (also available in a chat menu), names a room, and copies the invitation shown immediately after creation. The invitation appears only once; if lost, create a new room. The host can reopen existing rooms from Guest rooms, but cannot recover their original invitation.
• Guests open the invitation and join without signup, choose a name and a simple Culji skin tone, hair and background, then exchange text messages with the host and other guests. Anyone holding the link can join and view all guest-room history. Guest rooms are separate from existing private or group conversations: their members and history are not exposed to guests.
• The guest room is available for 24 hours or until the host closes it. Up to 20 guest sessions and 250 text messages are allowed. The host can have three open rooms and create up to 10 per UTC day; messages are rate limited. Chat updates poll roughly every three seconds while the page is visible, rather than using realtime push. Guest names are self-chosen and not verified; the host can close the room but cannot remove an individual guest or message. Link/session caps are not complete protection against automated abuse.
• The guest screen links to Veck.io, Poxel.io, Fortzone and the Eaglercraft launcher. These are independent third-party games, not synchronized or embedded in the guest room; availability, account requirements and ads depend on the provider. Eaglercraft requires a community-provided compatible build.
• Before the room closes or expires, a guest can select Save chat & Culji and sign up or sign in in the same browser tab. The signed-in account gets a private snapshot of the guest conversation at claim time, plus the selected look. Open More → Guest rooms → My saved guest chats to view/delete it or explicitly apply the saved skin tone, hair and background to the account’s Culji. It is a snapshot, not a joined or live regular chat; it will not receive future messages. Claimed guest sessions stop working. Closing the room or passing its expiry prevents new claims.
• Guest session capabilities live in browser session storage, not a permanent account. Reloading the same tab works, but closing or losing it may lose the session; save before that happens. A private database stores hashes of invitations/session capabilities, not their original values. Anyone with a link can forward it or copy chat content; closing the room cannot erase copies or saved snapshots. Guest chat is access-controlled, not end-to-end encrypted.
• A scheduled hourly cleanup removes expired or closed guest rooms seven days after expiry/closure. Saved account snapshots remain until the account holder deletes them. Cleanup is configured; its production execution has not been observed.

TESTS AND DEPLOYMENT
The guest-room backend has been applied to the connected project. Rollback-only database tests covered authorization, guest and host messages, token denial, expiry, session limits, archive ownership, claim and account-unlink token invalidation. An ephemeral live REST test successfully joined, read and sent as an unauthenticated guest, checked an invalid token was denied, and removed all test data afterward. Two browser clients tested guest join, safe text, polling, reload, arcade links, signup handoff and host close with mocked backend responses. Separate mocked tests covered host creation, private archive claim, applying the Culji look and deleting a snapshot. Real signup-to-claim and independent multi-device use remain untested. Previous room games, Watch Together, referral/cosmetic and responsive regressions passed.

The frontend has not been deployed. Extract and upload every file and folder, including guest.html and the hidden .nojekyll, to your GitHub Pages repository root. The earlier GitHub Actions startup failure has not been diagnosed or fixed. The service worker cache is v37. Do not upload the backend SQL or secrets to a public repository.

OTHER LIMITATIONS
YouTube and Spotify are shared link queues with independent playback, not a synchronized broadcast. Direct-video Watch Together only supports links to MP4/WebM files and provides approximate sync. Text-chat soundboard reactions play locally, not into call audio. Paddle checkout and Catcul+ rewards are unconfigured. Arcade providers may show ads. Game rankings and rewards are not cheat-proof.
